# Opening Goals (PWA)
Chess opening trainer: for every variation, teach the positional goal, then the strategy, then drill the line with spaced repetition. Personal app, installed on iPhone via Add to Home Screen.

## Stack
Vite + TypeScript (no UI framework), Chessground (board), chess.js (rules), ts-fsrs (scheduling), vite-plugin-pwa (offline). Progress in IndexedDB, optionally synced to Cloudflare D1 through one Worker (`worker/`, `wrangler.toml`, `docs/deploy-cloudflare.md`).

## Commands
- `npm run dev` / `npm run build` (typecheck + build)
- `npm run validate` checks every move in `content/*.json` is legal and has a note. Run it after any content edit.
- `npm run evals` runs Stockfish (Node, build time only) and writes `eval` onto every move. Run after content changes, then `npm run validate -- --require-evals`.
- `npm test` checks the progress merge logic. `npm run build` also typechecks `worker/`.
- `npm run grades` runs Stockfish (Node, build time only) over every position where the trained side moves and writes `src/grades.json`: the eval after each legal move and the engine's reply. Positions already in the file are skipped; run it after content changes (a test checks coverage). Never edit it by hand.
- `npm run try -- "d4 Nf6 c4 e5"` prints the engine eval after each move, for checking a candidate line.
- `npm run pv -- "d4 Nf6 c4 e5 dxe5 Nc6" ...` prints the engine's best continuation and eval after each given move list, for checking a common mistake. `npm run probe -- <opening> [variation]` lists the costly alternatives at each of the user's moves.

## Rules
- Content is static JSON in `content/` (one file per opening). The schema lives in `src/types.ts`. No paid API, no Claude and no engine at runtime in the client. The one allowed runtime AI is Workers AI on the free plan, called only from the Worker (`/api/explain`) to rephrase verified, rule-based mistake explanations; results are cached in D1 and the app always falls back to the rule-based text. It is never used during Drill.
- The user's side has exactly one accepted move per position. Any other legal move shows "<move> isn't part of this line." For captures and checks it adds a reason: a hand-written `why[<san>]` on the move if present, otherwise text built from the generated `caps` (engine's best reply and eval). Never name the line's own move in that text (it would give the answer away in Drill). `caps` is written by `npm run evals`; do not edit it by hand.
- Common mistakes: a move can carry `mistakes` (a natural wrong move, the punishing `line` after it, and a short `text`) and `versus` (why this move and not the one a near-identical position of another line uses). They are hand-written; `mistakes[].eval` is generated by `npm run evals`. Practice and Drill play a known mistake out on the board, then return to the position; Learn has a "Common mistake" button. Their texts never name the line's own move (the validator checks).
- chess.com import: Settings > "Your chess.com games" fetches the owner's newest 100 games the first time, then only games newer than the last import (looks at the newest 10), from chess.com's free public API (browser, no key, `src/chesscom.ts`) and `src/games.ts` replays each game against the lines (no engine): a move the owner played on their own turn that no matching line has, after at least one move of the line, is a deviation. The result is stored in `Progress.games` (each import is added to the stored one by `mergeImports`; the newer `at` wins the sync merge). `mistakesAt` makes those deviations replace the hand-written `mistakes` on every move that has game data (Practice, Drill, Learn, "why not" text); other moves keep the hand-written ones. Their text only says what was played and the results, so it never names the line's own move. The same import also records, per position and day, whether the owner played the line's move or left the line after two matching moves (`GameImport.recalls`); `gameAttempts` turns those into attempts that `masteryOf` adds to the log (no XP, never stored in `Progress.attempts`). `#/games` ("From your games") lists the deviations with a Practice button that starts the line at that position. Game mistakes are graded from `src/grades.json` (`src/grade.ts`: Playable, Inaccuracy ?!, Mistake ?, Blunder ??, by win-chance points lost against the engine's best move; thresholds are placeholders at the top of the file). The card says the grade, the pawns lost and the engine's reply, plays out that reply, and sets the eval bar; wrong moves in Practice/Drill get the same sentence. None of this text names the line's own move; the "From your games" review screen does, because it is not a drill. Tests: `scripts/test-games.ts`, `scripts/test-grade.ts`.
- Line viewer (`src/lineview.ts`): instead of paragraphs, each variation has a move-by-move picture (board, an arrow per move, eval bar, one-line caption, tappable move strip with swing dots). It is used on the opening page (folded) and in Learn's strategy step; only the first sentence of the strategy shows by default.
- "Need more explanation" (Learn, Practice, Drill) flags a move into `Progress.flags`; Settings lists and copies them for the next session. See the HANDOFF section on flagged moves; read it at session start.
- Questions: "Ask a question" stores `Progress.questions`; the daily-answers GitHub Action answers them into `src/answers.json` through a pull request (never edited by the app). See the HANDOFF section on questions.
- The message card has a fixed height on purpose: a taller message would shift the board and break Chessground's cached tap positions.
- Keep it a PWA on free tiers only. No card-on-file services, no secrets in client code. The sync token is a Worker secret and the user's own copy in IndexedDB; never commit `.dev.vars`.
- Content `status: "draft"` means a human has not reviewed the strategy text. Never mark `reviewed` yourself.
- GPL: Chessground is GPL-3.0, so keep the repo's source open if the site is published.
