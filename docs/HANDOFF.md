Phase 3 progress: `src/mastery.ts` (pure, tested in `scripts/test-mastery.ts`, run by `npm test`) computes a level per line from the attempt log plus the line's FSRS stability. Per position: a clean recall = one correct attempt, no hint, at most 10 s, with no wrong move earlier in the same visit; the position score counts distinct days with a clean recall; a slip takes one off (never below zero). Line level uses the weakest position: Learning (attempted), Familiar (every position clean on at least 1 day), Solid (2 days and stability of 7+ days), Mastered (3 days, stability of 21+ days, and a clean out-of-order recall at half or more of the positions). ## Mastery definition (decided; thresholds are placeholders to tune with real data)
- Mastery is per position; a line is capped by its weakest few positions, not the average.
- Position strength comes from FSRS stability in days: under 3, 3-14, 14-45, over 45 map to the upper levels.
- A correct recall counts only if unaided (no hint) and at a normal speed.
- Each level step needs correct recalls on separate days (3 for Mastered).
- Solid and Mastered also need out-of-order starts and a short "why" question.
- Soft slip (owner decision): a mistake lowers that position's strength through FSRS and flags it. It does not reset the whole line or its day count.
- No decay penalty while away; the level shows what was proven, and reviews come due as normal.
- Research notes: FSRS defines no "mastered" threshold (each app picks one). Chessbook scores mastery from review intervals (about 100 days = full credit). Successive relearning (correct to criterion across spaced sessions) is the supported idea; evidence on interleaving is mixed.

## Lessons
- Keep the message card at a fixed height. A taller message shifts the board and Chessground's cached bounds send taps to the wrong squares.
- Don't run `pkill -f <pattern>` with a pattern that also appears in your own command line; it kills the shell.
- Don't name the line's own move in "why not" text; it would give the answer away in Drill.
- `require('stockfish')(...)` returns one shared engine object, so a second engine in the same process breaks the first. Use a separate process (see `evals`).
- Engine evals depend a little on the order of earlier searches (hash table carry-over). Add new searches in a separate run, or every old eval moves by about 0.1.
- `pkill -f` again killed the shell this session (the pattern was in the command line). Find the PID with `ps` and `kill` it.
- `pkill -f vite preview` killed the shell once more in session 6. Start the preview server in the background and leave it, or find the PID with `ps`.
- When an old PR duplicates something now on `main` (as #37's flags did), keep `main`'s version and cut the PR down instead of merging two implementations.
- A bash heredoc without quotes (`<<EOF`) expands `${...}` inside JavaScript template strings; use `<<'EOF'` when writing scripts.
- `src/grades.json` must cover every position where the owner moves (a test checks it): after adding or changing a line, run `npm run grades` (about 25 minutes for everything; only new positions are searched).
